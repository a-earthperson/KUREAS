Knowledgebase with Uncertainty for Risk Engineering Analysis of Systems

KUREAS (pronounced “curious”) — an open-source suite of browser-based modules for facility reliability analysis and probabilistic risk assessment (PRA).

Each module is a single-file HTML application: no server, no build step, no installation. Open any module directly from this repository in a modern browser and load local project files. The suite implements SAPHIRE MAR-D file formats per NUREG/CR-7039 and exports to the OpenPSA Model Exchange Format.

Quick start Open any .html file in Chrome, Edge, Firefox, or Safari. Dependencies (React, Tailwind, Mermaid) load from CDNs at runtime. Project state is exchanged through downloadable .KNOW* files and SAPHIRE-compatible .FTL, .BED, .BEI, .ETL, and .SQC files. There is no step 3.

Module Launch Board

Six primary modules cover the analysis chain from hazard screening to report assembly. Each module is independently launchable; the natural workflow is iterative rather than strictly sequential.

KUREAS-HA — Hazard Analysis

KUREAS-ETL — Event Tree Logic

v1.0

Browser-based event tree visualization implementing a backwards-recursive layout algorithm that matches SAPHIRE branch placement. Loads .ETL headers, top-event types, logic sections, and sequence metadata; enriches sequences with .BED / .BEI / .SQC.

Choose by Analyst Concern

The same model can be approached from initiating events, success criteria, accident progression, file-format interchange, or evidence packaging. These views point to the relevant module and the artifacts it produces.

What initiates the challenge, and why is it in scope?

KUREAS-HA owns hazard structure, operating-state exposure, screening basis, frequency models, and fire-ignition estimates. The initiating-event basis stays inspectable rather than collapsing into a single number copied downstream.

Open Hazard Analysis

Relevant artifacts

  • Operating-state dependent hazard analysis with configurable time fractions.
  • NUREG-2169 fire-ignition bins, component counts, and propagation factors.
  • SAPHIRE-facing basic-event files (.BEI, .BED, .FTL) and HA_*.KNOW for downstream sequence work.

What has to work, what can fail, and what dominates risk?

KUREAS-SYS joins SSC inventories, failure modes, success-criteria logic, FMEA / P&ID context, derived fault-tree logic, common-cause failures, and importance measures in a single workspace.

Open System Evaluation

Relevant artifacts

  • SSC + failure-mode records with explicit probability model and source.
  • SYSTEM WORKS = … logic compiled to a fault tree with MCUB / BDD cut sets.
  • RIR, RRR, Probability of Contribution, and SWIM importance measures.

How does the facility response progress after the challenge?

KUREAS-SEQ represents Process Operational Logic: not just rows of an event tree, but reusable facility-response structure linking initiating events, functions, systems, end states, and consequences.

Open Process Operational Logic

Relevant artifacts

  • POL diagrams with reusable shared sub-diagrams (Mermaid.js).
  • Boundary conditions (Boolean / State / Percent / User-Defined) including fire-ignition data.
  • Event-tree structure generation from POL logic for downstream .ETL work.

What needs to round-trip with the PRA ecosystem?

KUREAS-FTL and KUREAS-ETL are the bridge to legacy and standards-based PRA artifacts. SAPHIRE MAR-D and OpenPSA MEF stay first-class formats alongside the native .KNOW* files.

Open FTL Open ETL

Relevant artifacts

  • SAPHIRE MAR-D import / export: .FTL, .BED, .BEI, .GTD, .FTC.
  • OpenPSA Model Exchange Format (.xml) for fault-tree interchange.
  • Event-tree visualization from .ETL with sequence-level cut sets from .SQC.

What evidence will survive review?

Module-level reports plus KUREAS-REPORT focus on traceability: selected tables, plots, references, generated diagrams, and reusable elements are assembled into a reviewer-facing record with Word page numbering and captions.

Open Report Generator

Relevant artifacts

  • .KNOW_RPT exports from HA, SYS, and SEQ for central assembly.
  • .ELEMENTS insertable boilerplate / reference packages.
  • .docx reports with TOC, captions, page numbering, and auto-update on .KNOW_RPT reload.

  │  KUREAS-ETL  │◄─────────│  SAPHIRE     │

Modules are not strictly sequential — any module can be opened first, work can proceed in parallel, and the .KNOW file family is the integration bus.

File Formats

Files are the integration bus. Native .KNOW* project files preserve the full engineering basis; SAPHIRE MAR-D and OpenPSA MEF formats provide round-trip with the broader PRA ecosystem.

Technical Stack

All modules are single-file HTML applications. Dependencies load from CDNs at runtime; no Node.js, npm install, or build process is required.

Regulatory References

KUREAS incorporates data and methodology from the following NRC publications:

  • NUREG-2169 — Nuclear Power Plant Fire Ignition Frequency and Non-Suppression Probability Estimation Using the Updated Fire Events Database. Table 4-4 fire ignition frequencies are built into KUREAS-HA.
  • NUREG/CR-7039 — Systems Analysis Programs for Hands-on Integrated Reliability Evaluations (SAPHIRE) Version 8. SAPHIRE file format specifications used throughout the suite.
  • NUREG-CR-6883 — The SPAR-H Human Reliability Analysis Method (Gertman, Blackman, Byers, Marble, Smith, 2005).
  • INL/EXT-10-18533 — SPAR-H Step-by-Step Guidance (Whaley, Kelly, Boring, Galyean, 2011).

Analyst Discipline

No server, no hidden state Every module runs from static HTML and exchanges files through browser upload / download, IndexedDB, and localStorage. The basis stays with the artifact rather than living on a remote service.
Traceability is preserved Hazard rationale, SSC metadata, failure-mode parameters, cut sets, importance measures, generated graphics, and report sections are all retained as inspectable artifacts — either inside .KNOW* files or as exported SAPHIRE / OpenPSA files.
Engineering judgment remains the analyst's Large models, exact quantification, CCF modeling, and any regulatory submissions should be benchmarked against the organization's accepted PRA toolchain. KUREAS-FTL and KUREAS-SYS ship with browser-based test harnesses (see Guides & QA) that can support that benchmarking.
